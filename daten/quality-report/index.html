堕天（Daten）品質確認報告

この文書について

堕天（Daten）0.8 系のソースコードを 2026年10月に点検し、見つかった問題を 2026年11月1日の時点でどこまで直したかをまとめました。

  • 対象：2026年10月26日に公開した 0.8.0 と、その後の修正を含む開発中の版（0.8.1 として公開予定）。Converter（Proxy の生成）、Bridge（神Excel と Proxy の間の転記、データの読出し・書込み）、Python パッケージを含みます。
  • 方法：AI によるソースコードの点検と、開発者の指示で AI が行った修正・テストの作成・Windows での再現試験です。開発者は、修正の方針と仕様上の判断を決め、テストデータを用意し、Excel での確認を行いました。
  • 限界：第三者機関による監査や認証ではありません。点検していない条件や、見つかっていない不具合がないことを保証するものでもありません。
  • 残る問題：直していない問題は、回避方法とともに「既知の問題と制限」で公開しています（5章）。

確認の方法

ソースコードを仕様と照らし合わせて問題を探し、コードだけでは決められないものは実際に動かして確かめました。

  1. 観点を決めた点検：次の6つの観点で、仕様どおりに動くかを調べました。
    • 処理ごとの役割が分かれているか（Proxy の生成、Proxy の更新、神Excel の更新）
    • データの範囲と数式を守っているか
    • 確定した Proxy の見出しを変えないか
    • 対象外のシートや範囲を変えないか
    • 見出しの名前とデータの行・列が正しく対応するか
    • 入力や既存のファイルを壊さないか
  2. 独立した検証：重要な指摘は、経緯を知らない別の AI のレビュー2系統に、結論を伏せて仕様とコードだけを渡し、別に判定させました。この検証で、新たに7件の問題が見つかりました。
  3. 実行による確認：Excel・Windows・Python の挙動によるものは、Windows で再現試験を行いました。修正の後は、通常版と Native AOT 版の両方で自動テストを走らせました。テストの期待値は、実装の出力ではなく仕様から作りました。
  4. 判断の訂正：点検での判断が実行結果と食い違ったときは、実行結果に合わせて訂正しました。たとえば、当初「ファイルのロックで入力は守られる」と判断した点は、再現試験で誤りと分かり、重要度を上げて修正しました。逆に、実際の Excel ではまず起きないと分かった2件は、重要度を下げました。

確認結果の概要

点検で挙げた問題36件のうち、10件を直し、5件を一部直しました。重要度「高」の5件では、データを壊すおそれのあったものをすべて直しています。

重要度 件数 直した 一部直した 未対応
高 5 3 1 1
中 14 4 3 7
低 17 3 1 13
計 36 10 5 21
  • 「高」で未対応の1件は、見出しの名前を作る規則の自動テストが足りないことです。製品の動作の誤りではなく、誤りが入ったときに気づく仕組みの不足です。
  • 「高」で一部直した1件は、転記の後に数式の計算結果が古いまま残る問題です。0.8 では再計算を行わず、既知の制限として知らせることにしました。
  • 未対応の多くは、Excel 以外のツールで作ったファイルや、見出しが数値だけの帳票など、条件が限られたものです。いずれも回避方法を公開しています。
  • この他に、画面の表示に関する6件とテストの不足に関する5件を、別に追跡しています。

観点ごとの判定は次のとおりです。

観点 点検時（10月） 現在（11月1日）
処理ごとの役割の分離 適合 適合
データの範囲と数式の保護 不備あり 一部に不備あり
確定した見出しの維持 適合 適合
対象外のシート・範囲の保持 適合 適合
見出しの名前とデータの対応 不備あり 一部に不備あり
入力・既存ファイルの破損 壊す経路あり 経路を塞いだ

対処した主な問題

もっとも重い問題は、出力先の指定によっては入力ファイルを上書きし得たことで、Windows で再現を確かめたうえで修正しました。

問題 起き得たこと 対処 確認
リンクなど別の名前のパスで、入力と同じファイルを出力先に指定できた（上書きを許可した場合） 入力の神Excel や Proxy が、正常終了のまま出力で置き換わる パスの文字列ではなく、ファイルの実体で同じかを判定する。処理中は入力を書込み禁止で開いておく。検証だけの実行でも同じ検査を行う Windows で修正前に再現。修正後は通常版80件・Native AOT 版75件の試験が成功
見出しのテキスト枠の位置の換算が誤っていた 枠の文字が隣の列の名前に入る 列幅の換算を Excel の規格どおりにし、標準フォントごとに実測した文字幅を使う。実測していないフォントでは警告を出す 修正前の式では通らない座標で自動テスト
数式を下へコピーした帳票（共有数式）を転記できなかった 実際の帳票の多くで Bridge が使えない 通常の数式として保護したまま、定数を転記できるようにした。配列数式・動的配列・データテーブルは引き続き拒否する 通常版・Native AOT 版の自動テスト
グラフシートを含むブックを開けなかった ブック全体が処理できない ワークシート以外は対象外として理由を示し、その内容が変わらないことを確かめる 通常版・Native AOT 版の自動テスト
転記では、使用期限を検査していなかった 期限を過ぎても転記できる 書込みを伴うすべての処理で期限を検査する 期限の当日と翌日を指定した自動テスト
日本語の Windows で Python から呼ぶと、出力を読めなかった 文字化けや、成功・失敗の誤判定 Bridge は UTF-8 で出力し、Python は厳密に復号して、読めなければ失敗として知らせる 日本語環境（CP932）を想定した自動テスト
マクロ有効ブックを .xlsx の名前で出力できた Excel で開けないファイルができる ブックの種類から必要な拡張子を決め、一致しなければ拒否する 自動テスト
神Excel で再計算した合計が Proxy に届かなかった Proxy の合計欄が古い値のまま kami-to-proxy で、神Excel に保存された計算結果を転記する。再計算済みかは確認できないため、その旨を報告する 自動テスト

テストの体制

修正のたびに、Converter・Bridge・Python の自動テストを一括して流し、ひとつでも失敗すればそこで止めています。実際の帳票を使った試験も含みます。

試験 内容 規模
一括の回帰試験 版の一致、ビルド、Converter、Bridge、シートの種類、画面の入力、変換、Python からの呼出しを順に実行し、失敗したら止める 修正ごとに実行。結果はログに保存
Python パッケージ 関数ごとの試験と、Bridge を実際に起動する試験。日本語の Windows（CP932）も含む 22件＋実際の Bridge との結合試験
実際の帳票 61シートの実際の帳票で、見出しのテキスト枠を読み取る テキスト枠 1,361個
Excel での実測との照合 テキスト枠がどの列に属するかを、Excel 上で実測した結果と照合する 89個。修正前は17個、修正後は89個すべてが一致
入力の保護 リンクなどで入力と同じファイルを出力先にしたとき、拒否され、入力が変わらないことを Windows で確かめる 通常版80件・Native AOT 版75件
扱えない数式の拒否 配列数式などを含む帳票を、実際のコマンドで拒否できるかを確かめる 12種類×4操作の48件。通常版・Native AOT 版とも
画面の入力の保護 読み込んだ後に元のファイルが変わったときに、生成を止める 9件。通常版・Native AOT 版とも

まだ確かめていない範囲もあります。

  • .NET を入れていない別の PC での実行と、インストール・更新・削除
  • 実際の Excel や他の表計算ソフトで保存し直したファイルでの試験（一部は、Excel を起動できない環境のため省略）
  • 非常に大きな帳票での処理時間
  • 画面の実際の操作、キーボードだけでの操作、スクリーンリーダーでの読み上げ

これらを確かめたときは、本書に結果を追記します。

0.8 での既知の制限と今後の対応

未対応の問題は、すべて同梱の「既知の問題と制限」（KnownIssues.md）に、起きることと回避方法を載せています。利用の前にお読みください。

特に注意していただきたいのは次の3点です。

  • 再計算をしません：proxy-to-kami・embed の後、数式の計算結果は古いまま残ります。提出や配布の前に、Excel で開いて再計算し、保存し直してください。
  • 見出しにかかる配列数式：配列数式・動的配列・データテーブルの結果が見出しの範囲にかかると、Converter がその範囲に文字を書き込むことがあります。このような範囲を見出し領域に含めないでください。
  • 生成された見出し名の確認：結合・非表示の行列・数値の見出しなどでは、意図と異なる名前になることがあります。Proxy を確定する前に、すべての名前を確認してください。

今後の対応の予定は次のとおりです。

  1. 見出しにかかる配列数式などを、Converter が生成の前に検出して拒否する
  2. その他の未対応の問題を、利用者の影響の大きいものから順に直す
  3. 見出しの名前を作る規則の自動テストを、仕様から作った期待値で拡充する

新しい版を公開したときは、本書の対処状況を更新します。
